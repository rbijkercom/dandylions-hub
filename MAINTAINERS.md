# Maintainers and contributing

**Only Ruben Bijker changes content in this hub.** Fabio and his Claude use it as read-only reference. Requests for changes (new sources, approved posts, corrections) go to Ruben, who edits and merges them.

## Where content comes from

| Hub file | Comes from |
| --- | --- |
| `design-system/tokens.json` | Site repo `rbijkercom/dandy-lions`: `src/app/(frontend)/styles.css` and `docs/design-system.md`; Figma file `ADAT7igJnBG5nvij5shy9V` (variables, brand guide). Curated by hand. |
| `design-system/brand-rules.md`, `social-formats.md` | Figma brand identity style guide and social media pack |
| `voice/*`, `sources/*` | Live site copy (`reference/copy.json` in the site repo, as published on https://dandy-lions.vercel.app) |
| `design-system/upstream/*` | Copied automatically by the sync workflow. Don't edit by hand. |
| `llms.txt`, `llms-full.txt` | Generated by `scripts/build_llms.py` from the Markdown and JSON files |

## Rules for edits

- Public repository and public website: add only content that is already published or cleared for publication. No secrets, private emails, phone numbers, addresses, client names or unpublished material. The only email addresses allowed are insights@dandylions.eu and consulting@dandylions.eu.
- Mark gaps as `[TO BE SUPPLIED BY RUBEN: ...]`.
- After editing Markdown or JSON, run `python3 scripts/build_llms.py` and commit the result. (The Pages workflow also regenerates both files on every deploy.)

## Publishing

`.github/workflows/pages.yml` builds the site with Jekyll and deploys it to GitHub Pages on every push to `main`: https://rbijkercom.github.io/dandylions-hub/

## Sync with the DandyLions site

`.github/workflows/sync-from-site.yml` runs every day at 05:00 UTC and on demand (Actions → "Sync design tokens from site" → Run workflow). It:

1. Checks out `rbijkercom/dandy-lions` (private) read-only.
2. Copies `src/app/(frontend)/styles.css` and `docs/design-system.md` into `design-system/upstream/`.
3. Regenerates `design-system/upstream/css-tokens.json` with `scripts/extract_css_tokens.py`.
4. If anything changed, opens or updates a pull request on branch `sync/site-tokens`. Ruben reviews it and updates `tokens.json` by hand where needed.

### Secret you must add

The site repo is private, so the workflow needs a read token:

- **Name:** `DANDY_LIONS_READ_TOKEN`
- **Type:** fine-grained personal access token
- **Resource owner:** rbijkercom. **Repository access:** only `rbijkercom/dandy-lions`
- **Permissions:** Repository → Contents: **Read-only** (Metadata: Read-only is added automatically). Nothing else.
- **Where:** this repo → Settings → Secrets and variables → Actions → New repository secret.
- Set an expiry and renew it before it lapses.

Without the secret the sync job stops with a clear error and changes nothing.

The workflow opens pull requests with the built-in `GITHUB_TOKEN`. For that, Settings → Actions → General → Workflow permissions has "Allow GitHub Actions to create and approve pull requests" switched on (already set when the hub was created).
